# Architecture Decisions Log (`docs/DECISIONS.md`)

This document records key architectural, security, and technical decisions made during the development of SkillSwap.

| Date | Decision | Options considered | Reason |
|---|---|---|---|
| 2026-10-21 | Use `PROJECT_STATUS.md` and `AGENT_RULES.md` with task plan files for agent tracking | Ad-hoc agent prompts vs strict documentation protocol | Prevents context loss, scope creep, and breaking changes across agent sessions |
| 2026-10-22 | Resolve `react-hooks/set-state-in-effect` using `useCallback` + microtask decoupling without disabling ESLint rules | `eslint-disable` vs `useCallback` + microtask queue vs restructuring component state | Maintains clean React 19 compiler compatibility, prevents cascading render cycles, and satisfies linter with zero rule disables |
| 2026-10-22 | Fix local dev port to 3001 using explicit `next dev -p 3001` in `package.json` | Port 3000 vs Port 3001 vs dynamic port assignment | Port 3000 is occupied by an active process (PID 30292). Hardcoding `-p 3001` ensures Next.js fails loudly rather than silently port-drifting and breaking NextAuth redirect callbacks. |
| 2026-10-22 | Restrict connection acceptance/rejection strictly to the recipient (`userBId`) | Allow either party vs recipient-only vs requester-only | In SkillSwap, `userAId` is the requester who initiated the connection request; allowing them to accept their own request violates the consent model. Requesters attempting to accept/decline receive 403 Forbidden. |
| 2026-10-22 | Preserve participant messaging across conversation states in `POST /api/messages` | Restrict strictly to `ACCEPTED` matches vs allow all match participant states | `/api/conversations` loads all user matches and `/chat` allows messaging across them (e.g. to coordinate pending swap details). Strictly locking to `ACCEPTED` would silently break existing UI messaging workflows. Participant checks (`getMatchForParticipant`) are strictly enforced. |
| 2026-10-22 | Eliminate `passwordHash` leaks via explicit safe select projections in `/api/user/profile` | `delete user.passwordHash` vs Prisma `select` | Explicit Prisma `select` (`SAFE_PROFILE_SELECT`) prevents the password hash from ever being retrieved from the database, eliminating any risk of serialization leaks. |
| 2026-10-22 | Standardize API input validation on Zod 4 schemas with `strip` behavior in `src/lib/validators` | Ad-hoc checks vs Joi/Yup vs shared Zod schemas | Zod is already in package.json; centralizing schemas enables code reuse across routes and future client-side forms. Stripping unrecognized keys prevents mass assignment. |
| 2026-10-22 | Handle empty string coordinate inputs via Zod preprocessor in `createEventSchema` | Require numbers strictly vs relax schema vs Zod preprocessor | `CreateEventDialog` sends empty strings `""` when lat/lng are omitted. Preprocessing `""` to `undefined` allows optional coordinates without breaking existing frontend component code. |
| 2026-10-22 | Standardize error response format as `{ "error": string, "details": [{ field, message }] }` via `src/lib/api-error.ts` | Custom error objects vs breaking change `{ message, errors }` vs backward-compatible `{ error, details }` | The existing frontend across all pages reads `data.error`. Preserving the top-level `"error"` string prevents UI breakages while adding `"details"` provides structured validation diagnostics. |
| 2026-10-22 | Normalize login email to lowercase and trimmed in `src/lib/auth.ts` | Case-insensitive collation vs runtime normalization in authorize | SQLite `@unique` is case-sensitive by default. Normalizing `credentials.email.toLowerCase().trim()` ensures login and registration behave identically and users can sign in regardless of input casing. |
| 2026-10-22 | Migrate string status/proficiency fields to native Prisma enums (`MatchStatus`, `AttendanceStatus`, `ProficiencyLevel`) | Unconstrained strings vs SQLite check constraints vs Prisma enums | Prisma 6.4 supports enums on SQLite via Prisma client validation, providing compile-time type safety across the database and TypeScript layers without data loss. |
| 2026-10-22 | Use composite index `@@index([userAId, userBId, matchedSkillId])` and runtime check on `Match` instead of schema `@@unique` | Force schema `@@unique` via `--accept-data-loss` vs composite index + route uniqueness check | `prisma db push` on SQLite requires `--accept-data-loss` when adding a new unique constraint to an existing populated table. The composite index optimizes lookups while runtime checks in `POST /api/matches` strictly guard against duplicates without risking data loss. |
| 2026-10-22 | Parallelize `GET /api/matches` queries via `Promise.all` and remove per-request `ensureSamplePeersExist` check | Serial database queries + per-request count check vs parallel batched queries | Removing `SELECT COUNT(*)` and executing `currentUser`, `otherUsers`, and `matches` lookups concurrently reduces request latency and eliminates query loops. |
| 2026-10-22 | Safe backward-compatible pagination with dual metadata contract (response object field + HTTP headers) across all list endpoints | Breaking payload redesign vs header-only vs dual metadata contract (object field + HTTP headers) | Preserves 100% backward compatibility with existing frontend consumers with zero UI edits. Default caps (100 matches/events/conversations, 200 messages, 50 reviews) protect server memory while returning complete current dataset. Dual contract provides metadata in JSON and HTTP response headers. |
| 2026-10-22 | In-memory sliding window rate limiter on globalThis with injectable clock and RATE_LIMIT_DISABLED testing switch | Hardcode limits vs Redis/Upstash in Phase 2 vs in-memory limiter | Avoids introducing cloud infrastructure dependencies before Phase 7 while immediately securing login and write endpoints; globalThis preserves state across Next.js HMR. Production guard strictly ignores RATE_LIMIT_DISABLED in production. |
| 2026-10-23 | Enforce one review per user pair via composite index and transactional concurrency check with 409 Conflict | Schema-level @@unique with --accept-data-loss vs application transaction + @@index([fromUserId, toUserId]) | Adding @@unique on SQLite requires destructive table recreation prompting for --accept-data-loss; composite index @@index([fromUserId, toUserId]) combined with a check-and-insert Prisma transaction guarantees race safety and returns HTTP 409 Conflict without risking database data loss. |
| 2026-10-23 | Strict privacy allow-list projection on GET /api/users/[id] and null average for 0 reviews | Unfiltered user include vs explicit Prisma select allow-list; 4.9 fallback vs null average | Never exposes email, passwordHash, or precise latitude/longitude over public profile API. Rating average returns null when count is 0 to avoid fabricating rating scores. On /reviews, form is conditionally replaced with already-reviewed notice (K22) to prevent failed submissions. |
| 2026-10-23 | Server-side proxy, 1 req/sec throttle gate, and 24h memory cache for OpenStreetMap Nominatim geocoding | Direct client-side calls vs server proxy; unthrottled requests vs global serial promise queue | Prevents leaking client IPs or user info to third parties, strictly adheres to Nominatim usage policy (1 req/sec max, custom User-Agent, attribution, 24h cache), and insulates client from upstream rate limits and failures with a friendly 503 fallback. |
| 2026-10-23 | Privacy-first Haversine distance calculation (whole-km peer rounding, 0.1 km event rounding) and reusable AddressSearch component | Exposing raw candidate coordinates to browser vs server-side distance calculation with privacy rounding | Never leaks another user's latitude or longitude to the browser. Peer distances are rounded to the nearest whole km (<1 km rounds to 0, rendered as 'Less than 1 km away'). Public events are rounded to 0.1 km. Reusable AddressSearch component extracted from CreateEventDialog powers both event hosting and profile location setting with zero code duplication. |
| 2026-10-23 | Add nullable latitude and longitude (Float?) columns to User model | Store coordinates in separate table vs nullable Float? columns on User | User model lacked geographic coordinates for distance calculation. Added nullable `latitude Float?` and `longitude Float?` to model User in `prisma/schema.prisma` with the owner's explicit approval and applied via non-destructive `prisma db push`, preserving all existing data and rows. |
| 2026-10-24 | Avatar upload with sharp WebP re-encoding, EXIF stripping, magic-number detection, and swappable storage interface | Direct original file saving vs client-side canvas vs server-side sharp re-encoding; cloud storage now vs swappable AvatarStorage interface with local disk | Direct file saving risks malicious payloads, decompression bombs, and EXIF GPS privacy leaks. Server-side sharp re-encodes to 512x512 WebP (quality 80) and strips all EXIF/GPS metadata. Input pixels are capped to 25 MP. Types are sniffed by magic bytes (JPEG/PNG/WebP only; SVG/HTML/PDF rejected). Storage is abstracted behind `AvatarStorage` (save, delete, read) defaulting to `storage/avatars/` outside public/, enabling clean drop-in replacement with cloud object storage in P7.1. |
| 2026-11-06 | Convert entire project from TypeScript to plain JavaScript (JSX) (Task C1) | Retain TypeScript vs partial conversion vs complete mechanical conversion | Project owner requirement for plain JavaScript. Mechanical conversion executed in stages (config, src/lib & Vitest tests, API routes, components/pages/layouts, seed & scripts) without behavior change. React stays; TypeScript syntax and packages removed. Static type checking retired in favor of runtime Zod validation and comprehensive test & check suites. |
| 2026-11-06 | Migration to decoupled React (Vite) frontend + separate Express backend (M1 Foundation) | Monolithic Next.js vs Next.js API-only vs Express + Vite | Owner requested plain React (Vite) frontend with separate Express backend in plain JavaScript (ESM). Strangler fig migration strategy keeps legacy Next.js app running untouched on port 3001 while Express is incrementally built in `server/` on port 4000 sharing the exact same SQLite database and Prisma schema. Replaced NextAuth with signed HS256 JWT in HttpOnly SameSite=Lax cookie (`skillswap_session`) carrying user ID, with dummy bcrypt timing-attack mitigation. Vite dev proxy eliminates CORS. P3.5 (host event edit/cancel, attendee limits) will be built natively in Express under M2. |
| 2026-11-06 | Implement P3.5 natively in Express backend with nullable maxAttendees and cancelledAt columns, capacity enforcement, and zero extra dependencies (Task M2) | Multer vs native Node 24 Request formData; separate cancellation table vs cancelledAt timestamp | Added nullable `maxAttendees Int?` and `cancelledAt DateTime?` to `model Event` via approved, non-breaking `prisma db push`. Kept zero extra dependencies in `server/` (apart from allowed `sharp`): parsed multipart avatar uploads using native Node 24 `Request.prototype.formData()`. Built pure business logic module `event-rules.js` and isolated integration tests on temporary DB copy (`p35-write.test.js`). Cancelled events visible only to hosts and attendees. Joining capacity strictly enforced in Prisma transaction with 409 Conflict. Toggling OFF RSVP is always permitted. Ported all remaining Next.js routes to Express with 100% parity (36/36 parity assertions passed against port 3001 and port 4000). |
| 2026-11-06 | React (Vite) client scaffold with same-origin dev proxy and centralized AuthContext (Task M3) | Client-side CORS vs Vite dev proxy; Redux/Zustand vs React Context | Built decoupled React 19 SPA in `client/` using Vite, React Router v7, and Tailwind CSS v4. Vite dev proxy routes `/api` to Express on port 4000 while preserving browser `Origin` (`http://localhost:5173`) to satisfy Express CSRF validation. Centralized `AuthContext` provides session state (`loading`, `authenticated`, `unauthenticated`), auto-reconnects on mount, and supports auto-login after register. Ported 4 core pages (`/`, `/auth`, `/dashboard`, `/profile/:id`) and rendered explicit migration cards for placeholder pages deferred to M4. Verified via 27 unit tests and 21 automated smoke checks with 0 DB mutations. |
| 2026-11-06 | Port Chat, Reviews, and Profile Setup pages to React Vite client with resilient polling and race prevention (Task M4a) | Global lock vs per-match in-flight guard; immediate state update + auth refresh vs reload | In `ChatPage.jsx`, implemented resilient 3s polling with per-match in-flight protection (`inFlightMatchIdRef`), tab visibility pause/resume via `document.visibilitychange`, and active conversation switch discard guard (`activeMatchIdRef`). Auto-scroll preserves scrollback reading position (`isNearBottom`). In `ReviewsPage.jsx`, wired 1-5 star selector, 409 duplicate conflict handling, and pagination. In `ProfileSetupPage.jsx`, eliminated avatar upload race condition by immediately updating local state and calling `AuthContext.refresh()`, guaranteeing subsequent profile saves submit the newly generated avatar URL. Extracted reusable `AddressSearch.jsx` with request counter ignoring stale out-of-order geocodes and OpenStreetMap attribution. |
| 2026-11-06 | Direct Leaflet integration with bundler icon resolution, XSS-safe DOM popups, and unified EventDialog with P3.5 capacity handling (Task M4b) | `react-leaflet` vs direct `leaflet`; HTML string popups vs DOM element popups; separate create/edit modals vs unified EventDialog | Direct `leaflet` dependency matching root `^1.9.4` without `react-leaflet` keeps client lean and matches legacy implementation. Resolved bundler icon asset paths via local image imports (`leaflet/dist/images/marker-icon.png`). Popups construct DOM nodes with `textContent` rather than string interpolation, preventing XSS injection. Map instance is cleaned up on unmount (`map.remove()`) and `invalidateSize()` handles view toggles. Unified `EventDialog.jsx` uses key-based form re-initialization (satisfying React compiler without `useEffect` state sync), differential patching (`buildEventPatch` sending only modified fields), and cancellation confirmation sub-dialog. `<input type="datetime-local">` converts to ISO UTC string via `fromLocalInputValue` preserving local time. Capacity limits (`maxAttendees`) and cancelled states are enforced with 409 Conflict handling, while RSVP toggle OFF remains unconditionally permitted.
| 2026-11-11 | Decommission Next.js monolith, add Express production SPA serving with Helmet CSP, and replace root with thin Node orchestrator (Task M5) | Dual Next/Express tree vs complete removal of `src/` + Next dependencies; default Helmet CSP vs explicit `useDefaults: false` CSP omitting `upgrade-insecure-requests`; delete `public/` vs preserve `public/uploads/avatars/` | Next.js migration M1–M4b achieved 100% route and page parity, so `src/`, Next configs, root Next dependencies, and port-3001 scripts/snapshots were removed cleanly while keeping all historical plan docs. Root `package.json` now delegates cleanly via `scripts/dev.mjs` and `scripts/start.mjs` (zero new dependencies). In `NODE_ENV=production`, Express serves `client/dist/assets` (`Cache-Control: public, max-age=31536000, immutable`), serves `index.html` with `no-cache` for SPA deep links accepting HTML, preserves JSON 404 for `/api/*`, blocks `..` traversal paths with 400, and applies the exact CSP (`useDefaults: false` avoids `upgrade-insecure-requests` breaking HTTP `localhost:4000` verification). `public/uploads/avatars/` stays because `server/.env` configures `AVATAR_STORAGE_DIR="../public/uploads/avatars"` and stores existing WebP avatars; `avatar-storage.js` now resolves relative paths against `server/` regardless of cwd.
| 2026-11-13 | Migrate Data Layer from SQLite to MongoDB Replica Set via Prisma MongoDB Connector (Task MG1) | UUID string primary keys with `@map("_id")` vs BSON ObjectId (`@db.ObjectId`); MONGODB_URL vs DATABASE_URL; snapshot isolation transaction handling vs atomic write-and-recount compensation | Retained plain UUID string primary keys via `id String @id @default(uuid()) @map("_id")` and plain String foreign keys, ensuring 100% zero-regression contract compatibility with existing clients, check scripts, and SQLite archive data. Added compound unique constraints `Match @@unique([userAId, userBId, matchedSkillId])` and `Review @@unique([fromUserId, toUserId])`. Mapped MongoDB replica set write conflict error `P2034` alongside unique violation `P2002` to standard 409 Conflict. Implemented insert-then-recount with deterministic compensation for RSVP capacity to strictly guarantee `goingCount <= maxAttendees` under concurrent requests. Adapted `GET /api/events` filter for MongoDB's missing-field semantics (`OR: [{ cancelledAt: null }, { cancelledAt: { isSet: false } }]`). Ephemeral test database harness enforces strict `_test_` naming guard, preventing any test mutation from touching the production/main database or external project databases (`smart_city`, `zipi`). `prisma/dev.db` backed up to `D:\dev.db.backup19` and preserved byte-identical. |
| 2026-11-16 | Phase 6 Security Hardening, Anti-Abuse Rules, Code Splitting & CI Automation (Task P6) | Public reviews vs session required; unconstrained messaging vs pending-match rate limits; single monolithic client bundle vs route-level lazy loading; manual testing vs dual-job GitHub Actions CI | 1) `GET /api/reviews` now requires an active user session (401 Unauthorized for unauthenticated requests) since reviews are inherently bound to peer interaction context and the frontend only invokes this endpoint from authenticated views. 2) Mitigated messaging abuse (K17): on `PENDING` connection requests, only the requester may send up to 3 introductory messages (409 Conflict thereafter), while the recipient cannot reply until accepting (409 Conflict); `DECLINED` requests reject all messages (409 Conflict). 3) Added `Sec-Fetch-Site: cross-site` rejection (403 Forbidden) on state-changing methods to strengthen CSRF defense. 4) Expanded Helmet CSP `img-src` to `["'self'", 'data:', 'blob:', 'https:']` allowing Unsplash avatar photos in production. 5) Modernized security headers (`Permissions-Policy: camera=(), microphone=(), geolocation=()`, `COOP: same-origin`, `Referrer-Policy: strict-origin-when-cross-origin`, HSTS in prod, `x-powered-by` off). 6) Eliminated IP-spoofing rate limit bypass by relying on Express `req.ip` rather than manual `x-forwarded-for` parsing, configurable via `TRUST_PROXY`. 7) Implemented route-level code splitting in `client/src/App.jsx` with `React.lazy` and `Suspense`, dropping the entry bundle from 650 kB to 333 kB raw (~105 kB gzip) and isolating Leaflet to `EventsPage`. 8) Established GitHub Actions CI workflow (`.github/workflows/ci.yml`) with containerized MongoDB 7 replica set integration testing and weekly Dependabot automation (`.github/dependabot.yml`). |
| 2026-11-17 | Phase 7a Deployment Preparation: Accept/Decline UI, Avatars in MongoDB (`AvatarFile`), Production Data Tools, & Render Blueprint | Disk storage vs Cloudinary/S3 vs MongoDB `AvatarFile`; breaking API change vs additive `requestDirection`; upsert vs clean restore with `--skills-only`; multi-instance scaling vs single-instance constraint | 1) Additive `requestDirection` ("SENT" \| "RECEIVED" \| null) added to `/api/matches`, `/api/conversations`, and `/api/users/:id` without modifying schema or breaking contracts, empowering recipient UI to Accept/Decline on Dashboard, Profile, and Chat. 2) Avatars stored directly in MongoDB via `AvatarFile` model with fallback to disk, completely preventing data loss on Render's ephemeral disk while avoiding external object storage costs. 3) `import-backup.mjs` validates JSON, constraints, enums, and foreign-key integrity in topological order, offering `--skills-only` for clean launches and refusing to run on non-empty destinations. Demo quick-fill button guarded by `!import.meta.env.PROD`. 4) Standardized Node 22 engines, added `debian-openssl-3.0.x` Prisma binaryTarget, created `render.yaml` Blueprint, and clearly documented the single-instance constraint due to in-memory rate limiting and Nominatim caching. |
| 2026-11-17 | Phase 7b Production Hardening: Logging, Account Deletion, Hand-Written OAuth PKCE, Resend Email, & Launch Prep | Passport/next-auth vs hand-written OAuth PKCE; automatic account linking vs anti-pre-hijacking error; sync email sending vs fire-and-forget; client-side delete vs cascading DB cleanup | 1) **Production Logging**: Production logs strictly 1 JSON line per request (`timestamp`, `requestId`, `method`, `path` without query, `status`, `durationMs`, and `userId` if logged in). Strictly omits headers, cookies, bodies, query strings, IP addresses, and emails. Injected `X-Request-Id` UUID header. Process crash handlers log redacted error JSON (stripping MongoDB credentials) before exiting non-zero. Added `GET /api/health/db` with 3s ping timeout and 30 req/min/IP rate limiting. 2) **Account Deletion**: `DELETE /api/user/account` requires `confirm: "DELETE"` and password (unless OAuth account). Deletes user and performs complete cascading cleanup of skills, matches, messages, reviews given and received, hosted events and attendees, RSVPs elsewhere, avatars (DB and disk), and OAuth accounts, leaving zero orphaned records across all collections. 3) **Google OAuth PKCE**: Hand-written OAuth 2.0 PKCE authorization code flow with zero new npm packages. Uses built-in `crypto` for code verifiers, SHA-256 code challenge, and timing-safe state comparison in an HttpOnly 10-minute cookie (`skillswap_oauth`). Prohibits auto-linking to existing email accounts to prevent account pre-hijacking (`/auth?error=account_exists`). 4) **Email Notifications**: Resend HTTP API integration (`server/src/lib/email.js`) via built-in `fetch` with 5s timeout. Dormant if unconfigured; dry run mode logs domain only. Fire-and-forget dispatch after database writes for connection requests, request acceptances, and event cancellations (capped at 50 attendees, excluding host). Rate limited to 5/hr and 20/day per recipient, and 1 request email per pair per 24h. 5) **Cleanup**: Removed unused Next.js starter components (`table.jsx`, `scroll-area.jsx`) reducing CSS bundle size; retained zero-dependency policy. |
