## 2. Current Matching Engine Analysis

### Step-by-Step Execution in `GET /api/matches`
1. **Authentication Check**: Calls `requireSession()` (verifies session token).
2. **Database Peer Seeding Check**: Calls `ensureSamplePeersExist()`, which executes `prisma.user.count()`. If `< 3`, it loops over sample peers and issues dozens of upserts. Even when count >= 3, it executes a database count query on every single request.
3. **Current User Fetch**: Calls `prisma.user.findUnique` with nested `skillsTeach -> skill` and `skillsLearn -> skill`.
4. **Learn Skills Lowercasing**: Extracts current user's learning skills by name:
   `const userLearnSkillNames = currentUser.skillsLearn.map((sl) => sl.skill.name.toLowerCase());`
5. **Other Users Fetch**: Calls `prisma.user.findMany({ where: { id: { not: currentUser.id } } })` including nested `skillsTeach -> skill`, `skillsLearn -> skill`, and `reviewsReceived -> { rating }`.
6. **Matches Fetch**: Calls `prisma.match.findMany({ where: { OR: [{ userAId }, { userBId }] } })`.
7. **In-Memory Matching Loop (`otherUsers.map`)**:
   - Calculates average rating:
     `totalReviews > 0 ? parseFloat((sum / totalReviews).toFixed(1)) : 4.9;`
   - Finds skills peer teaches that user wants:
     `matchingSkillsUserWants = peer.skillsTeach.filter(st => userLearnSkillNames.includes(st.skill.name.toLowerCase()))`
   - Finds skills user teaches that peer wants:
     `matchingSkillsPeerWants = currentUser.skillsTeach.filter(st => peerLearnSkillNames.includes(st.skill.name.toLowerCase()))`
   - Determines mutual match:
     `isMutual = matchingSkillsUserWants.length > 0 && matchingSkillsPeerWants.length > 0`
   - Determines connection status from `matches`:
     Looks up match where `(userAId === current && userBId === peer) || (userAId === peer && userBId === current)`. If found, `connectionStatus = existingMatch.status; matchId = existingMatch.id;`, otherwise `"NONE"` and `null`.
   - Determines matched skill name:
     If `matchingSkillsUserWants.length > 0`, takes first matching skill name: `matchingSkillsUserWants[0].skill.name`.
     Else if `peer.skillsTeach.length > 0`, takes `peer.skillsTeach[0].skill.name`.
     Else fallback to `"General Skill Swap"`.
   - Maps peer attributes and skills.
8. **Response Packaging**:
   Returns `{ currentUser: { id, name, email, location, teachCount, learnCount }, matches: matchResults }`.

### Query Count Breakdown (Baseline: 13 Queries)
When `GET /api/matches` runs, Prisma logs show 13 queries:

11. `SELECT ... FROM Skill WHERE id IN (...)`

## 3. Planned Pure-Function Design (`src/lib/matching.ts`)

Extract the business logic into pure functions with strict TypeScript types:
- `calculateRating(reviews: Array<{ rating: number }>): { avgRating: number; reviewCount: number }`
  - Returns `avgRating: 4.9` and `reviewCount: 0` when reviews is empty.
  - Returns `parseFloat((sum / len).toFixed(1))` and length when reviews exist.
- `findSkillMatches(userLearnSkillNames: string[], peerTeachSkills: SkillItem[]): SkillItem[]`
  - Case-insensitive comparison: `userLearnSkillNames.includes(skill.name.toLowerCase())`.
- `determineMatchedSkillName(matchingSkillsUserWants: SkillItem[], peerTeachSkills: SkillItem[]): string`
  - Returns first wanted skill, or first taught skill, or `"General Skill Swap"`.
- `findConnectionStatus(peerId: string, currentUserId: string, matches: MatchRecord[]): { connectionStatus: string; matchId: string | null }`
  - Checks bidirectional relationship between `currentUserId` and `peerId`.
- `computePeerMatch(currentUser: MatchingUser, peer: MatchingPeer, matches: MatchRecord[]): PeerMatchResult`
  - Computes single peer match payload.
- `computeAllMatches(currentUser: MatchingUser, otherUsers: MatchingPeer[], matches: MatchRecord[]): MatchesApiResponse`
  - Master pure function that returns the full API response object.

## 4. Planned Query Strategy in API Route

1. Avoid running `ensureSamplePeersExist()` on every request. Seeding is only needed if `User` table is completely empty, not on every user match query.
2. Query `currentUser` and `otherUsers` cleanly.
3. Run fixed batched queries (zero loops, zero N+1).

## 5. Vitest Unit Test Suite (`src/lib/matching.test.ts`)

1. **Mutual Swap**: Flagged `isMutual: true` when A teaches what B wants AND B teaches what A wants.
2. **One-Way Match**: Not flagged mutual when only one direction has overlapping skills (`isMutual: false`).
3. **No Overlap**: Returns `isMutual: false` and falls back to first peer taught skill or `"General Skill Swap"`.
4. **No Skills Peer**: Handles users with empty `skillsTeach` and `skillsLearn` (e.g. "ray" in dashboard) without crashing, returning `"General Skill Swap"` and empty skill arrays.
5. **Self-Exclusion**: Current user never appears in their own results.
6. **Connection Status**:
   - Returns `"NONE"` when no match exists.
   - Returns `"PENDING"` with match ID when connection request is pending (sent or received).
   - Returns `"ACCEPTED"` with match ID when connection is accepted.
   - Handles `userAId` and `userBId` roles correctly in both directions.
7. **Rating Calculation**:
   - Returns `avgRating: 4.9` and `reviewCount: 0` for peers with no reviews.
   - Accurately averages ratings to one decimal place (e.g. `[5, 4] -> 4.5`).
8. **Case-Insensitive Skill Matching**: Matches skills across different casing (e.g. `"JavaScript / React"` vs `"javascript / react"`).
9. **Empty Inputs**: Handles empty arrays cleanly without crashing.
