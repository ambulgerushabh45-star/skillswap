# P3.1 Plan — Public Peer Profile Page & UI Hardening

## 1. Objectives & Scope
1. Implement a public peer profile API endpoint `GET /api/users/[id]` with strict privacy controls (zero email, passwordHash, or coordinate leakage).
2. Build responsive profile page `/profile/[id]` with dynamic action buttons based on viewer relationship (`isSelf`, `NONE`, `PENDING`, `ACCEPTED`, `DECLINED`, `hasReviewed`).
3. Add peer profile links on dashboard cards, chat header, and reviews page.
4. Resolve **K22**: on `/reviews`, show "You have already reviewed this person." when `viewer.hasReviewed` is true.
5. Fix placeholder rating display on dashboard cards: show "New" badge when `reviewCount === 0` instead of "⭐ 4.9 (0)".
6. Unit tests with fake inputs and read-only automated check script `scripts/profile-check.mjs`.

---

## 2. Privacy & Allow-List Strategy
Public profile endpoints must NEVER expose sensitive user credentials or precise geolocation coordinates.
- **Forbidden Fields**:
  - `email`
  - `passwordHash`
  - `lat` / `latitude`
  - `lng` / `longitude`
  - Any internal audit fields unnecessary for the public view
- **Allowed Prisma Select Projection**:
  - User: `id`, `name`, `avatarUrl`, `bio`, `location`
  - `skillsTeach`: include `skill` (`id`, `name`, `category`), `proficiency`
  - `skillsLearn`: include `skill` (`id`, `name`, `category`)
  - Reviews: `id`, `rating`, `comment`, `createdAt`, `fromUser` (`id`, `name`, `avatarUrl`)
- **Rating Summary Contract**:
  - When `reviewCount === 0`: `rating.average` must be `null` (not 4.9).
  - When `reviewCount > 0`: `rating.average` is rounded to 1 decimal place (`parseFloat(avg.toFixed(1))`).

## 3. API Contract: `GET /api/users/[id]`
- **Authentication**: `requireSession()` guard (401 Unauthorized for anonymous callers).
- **Validation**: `parseParams(rawParams, userIdParamSchema)` (400 Bad Request for empty/invalid id).
- **Existence**: Returns 404 Not Found if user is not in database.
- **Pagination for Reviews**: Supports `page` and `limit` query parameters with default cap of 50 reviews, sorted by `createdAt: "desc"`, `id: "desc"`.
- **Response Shape**:
  ```json
  {
    "user": {
      "id": "uuid",
      "name": "Jane Doe",
      "image": "https://...",
      "avatarUrl": "https://...",
      "bio": "Bio text",
      "location": "Bengaluru, India",
      "skillsTeach": [
        { "name": "React", "category": "Programming", "proficiencyLevel": "Expert" }
      ],
      "skillsLearn": [
        { "name": "Guitar", "category": "Music" }
      ]
    },
    "rating": {
      "average": 4.8,
      "count": 5
    },
    "reviews": [
      {
        "id": "uuid",
        "rating": 5,
        "comment": "Great session!",
        "createdAt": "2026-10-23T...",
        "fromUser": {
          "id": "uuid",
          "name": "Alex Kumar",
          "avatarUrl": "https://..."
        }
      }
    ],
    "pagination": {
      "total": 5,
      "page": 1,
      "limit": 50,
      "totalPages": 1,
      "hasNextPage": false,
      "hasPrevPage": false
    },
    "viewer": {
      "isSelf": false,
      "matchStatus": "NONE" | "PENDING" | "ACCEPTED" | "DECLINED",
      "matchId": "uuid" | null,
      "hasReviewed": false
    }
  }
  ```

## 4. Page Architecture: `/profile/[id]`
- **Client Component** (`src/app/profile/[id]/page.tsx`):
  - State: `profile`, `loading`, `error`, `actionLoading`, `connectError`.
  - Header: Back button, Avatar, Name, Location pin, Rating badge ("New" or "⭐ 4.8 (5 reviews)").
  - Action Button Area:
    - `viewer.isSelf === true` -> "Edit Profile" button linking to `/profile/setup`.
    - `matchStatus === "NONE"` -> "Connect" button calling `POST /api/matches`, updates status to `PENDING` on 201.
    - `matchStatus === "PENDING"` -> Disabled button "Request Pending" with clock icon.
    - `matchStatus === "ACCEPTED"` -> "Message" button linking to `/chat` and conditional "Rate & Review" button linking to `/reviews?toUserId=...` (only shown if `hasReviewed === false`).
    - `matchStatus === "DECLINED"` -> Neutral note: "Connection request was declined".
  - Details Card:
    - About / Bio section.
    - Skills Offered / Can Teach badges with proficiency labels.
    - Skills Wanted / Wants to Learn badges.
  - Reviews Card:
    - List of reviews with star rating, reviewer avatar, name, date, comment.
    - Empty state: "No reviews yet. Connect and complete a skill session to leave the first review!"
  - Not Found / Error State:
    - Friendly "Profile Not Found" card with link back to `/dashboard`.
