# Implementation Plan — P3.4: Avatar Upload & Processing

## 1. Task Overview & Context
Enable users to upload a profile photo from their device on the profile setup page (`/profile/setup`).
The uploaded image is securely validated via magic bytes, resized and auto-oriented via `sharp`, stripped of all privacy-sensitive metadata (such as EXIF GPS tags), re-encoded as WebP, and stored on local disk behind a storage interface (`src/lib/avatar-storage.ts`) in `storage/avatars/`. Photos are served to authenticated users via `GET /api/avatars/[file]`.

---

## 2. Security Checklist & Attack Mitigations
- **Magic Byte Validation**:
  Never trust file extensions or `Content-Type` header sent by browser. Detect real byte signatures:
  - JPEG: `0xFF, 0xD8, 0xFF`
  - PNG: `0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A`
  - WebP: RIFF `0x52, 0x49, 0x46, 0x46` (bytes 0-3) and `WEBP` `0x57, 0x45, 0x42, 0x50` (bytes 8-11)
  Reject all other formats (SVG, GIF, PDF, HTML, scripts) with 400/415.
- **Always Re-encode & Strip Metadata**:
  The uploaded image is decoded and re-encoded using `sharp` to WebP at quality 80. `sharp` drops all metadata (EXIF, IPTC, XMP) by default (proven via unit test). Auto-orientation (`.rotate()`) is applied based on EXIF before stripping.
- **Decompression Bomb Protection**:
  Sharp input is configured with `limitInputPixels: 25000000` (~25 megapixels) and `failOnError: true` to prevent memory exhaustion from zip/decompression bombs.
- **File Size Limits**:
  - Early rejection: inspect `Content-Length` header; if $> 2.5\text{ MB}$, reject with HTTP 413 without parsing body.
  - Payload rejection: check `file.size > 2 * 1024 * 1024` ($2\text{ MB}$), reject with HTTP 413.
- **Path Traversal Prevention**:
  File names follow `<userId>-<16 lowercase hex chars>.webp`.
  `GET /api/avatars/[file]` strictly validates the `file` param against regex `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}-[0-9a-f]{16}\.webp$` BEFORE touching disk. Any traversal (`..`, `/`, `\`, `%2e%2e`) is rejected with HTTP 400.
- **Ownership & Profile PUT Validation**:
  `PUT /api/user/profile` validates that any `avatarUrl` pointing to `/api/avatars/<file>` starts with the caller's own `userId`. Users cannot claim or display another user's avatar. Arbitrary relative paths (`/etc/passwd`, `../`) are rejected with HTTP 400.
- **Compensating Action on Error**:
  In `POST /api/user/avatar`, if disk write succeeds but database update fails, the newly written file is immediately deleted and HTTP 500 returned.
- **Cache Invalidation via Unique Filenames**:
  Each upload generates a new 16-hex random suffix. Replaced files are deleted from storage only if they pointed to our `/api/avatars/` path.

## 3. Architecture & Storage Interface
- **Interface** (`src/lib/avatar-storage.ts`):
  ```ts
  export interface AvatarStorage {
    save(fileName: string, buffer: Buffer): Promise<void>;
    delete(fileName: string): Promise<boolean>;
    read(fileName: string): Promise<Buffer | null>;
  }
  ```
- **Local Disk Implementation**:
  Default path: `<workspace>/storage/avatars`.
  Overridable via `AVATAR_STORAGE_DIR` environment variable.
  Directory created recursively on first use.
- **Git & Env**:
  Add `storage/` to `.gitignore`.
  Add `AVATAR_STORAGE_DIR` to `.env.example`.
- **Known Issue**:
  Local disk storage will not persist across serverless deployments (e.g. Vercel). Document in `PROJECT_STATUS.md` for P7.1 cloud migration (S3/R2/Blob).

## 5. Implementation Steps

### Step 1: Install sharp & update gitignore / env
- Run `npm install sharp`.
- Add `storage/` to `.gitignore`.
- Add `AVATAR_STORAGE_DIR=./storage/avatars` to `.env.example`.

### Step 2: Implement pure module `src/lib/avatar.ts`
- `detectImageType(buffer: Buffer): "jpeg" | "png" | "webp" | null` checking header bytes.
- `processAvatar(buffer: Buffer): Promise<{ buffer: Buffer; contentType: "image/webp" }>` using sharp:
  - `limitInputPixels: 25000000`, `failOnError: true`
  - `.rotate()`
  - `.resize(512, 512, { fit: "cover", position: "centre" })`
  - `.webp({ quality: 80 })`
- `buildAvatarFileName(userId: string, randomHex?: string): string`.
- `isValidAvatarFileName(name: string): boolean`.
- `isValidAvatarUrl(url: string, currentUserId?: string): boolean`.

### Step 3: Implement storage `src/lib/avatar-storage.ts`
- `LocalDiskAvatarStorage` with `save`, `delete`, and `read`.
- Export singleton `avatarStorage`.

### Step 4: Unit tests in `src/lib/avatar.test.ts`
- Test magic bytes sniffing (JPEG, PNG, WebP, SVG, GIF, PDF, empty, text).
- Test `processAvatar` output (dimensions $\le 512\times 512$, format WebP, non-square cropped to square).
- Test EXIF metadata stripping (generate JPEG with EXIF tags in test, process it, verify sharp metadata has no EXIF or GPS tags).
- Test corrupt image throws controlled error.
- Test filename building and strict regex validation against traversal (`../`, `/`, `%2e%2e`, uppercase, invalid extension).

### Step 5: Routes
- `POST /api/user/avatar`:
  - `requireSession` (401)
  - Rate limit: 10 uploads/hr (`avatar:upload:<userId>` -> 429)
  - Content-Length > 2.5MB -> 413
  - Multipart form parsing (`file`) -> 400 if missing
  - Buffer length > 2MB -> 413
  - Magic bytes -> 400/415
  - Sharp processing -> 400 if corrupt
  - Write to storage
  - Update user in DB; delete on DB error (500)
  - Delete old file if it was `/api/avatars/`
  - Return `{ avatarUrl: "/api/avatars/<file>" }`
- `DELETE /api/user/avatar`:
  - `requireSession` (401)
  - Delete old file if `/api/avatars/`
  - Update user `avatarUrl: null`
  - Return `{ avatarUrl: null }`
- `GET /api/avatars/[file]`:
  - `requireSession` (401)
  - Await `params` (Next.js 16 Promise)
  - Validate `file` with `isValidAvatarFileName` -> 400 if invalid
  - Read from storage -> 404 if missing
  - Return `Response` with `Content-Type: image/webp`, `X-Content-Type-Options: nosniff`, and `Cache-Control: private, max-age=31536000, immutable`

### Step 6: Profile PUT ownership validation
- In `src/lib/validators/profile.ts`: allow empty, http(s) URL, or `/api/avatars/<validName>`.
- In `src/app/api/user/profile/route.ts`: if `avatarUrl` starts with `/api/avatars/`, enforce `fileName.startsWith(auth.user.id + "-")`. Return 400 otherwise.

### Step 7: UI in `src/app/profile/setup/page.tsx`
- Photo avatar preview using `AvatarImage` with `AvatarFallback` (initial letter).
- "Upload photo" button with file picker.
- "Remove photo" button calling `DELETE /api/user/avatar`.
- Info hint: *"JPG, PNG or WebP, up to 2 MB. Your photo is resized and stripped of hidden data."*.
- Error banner on upload failure.
- **Race Fix**: Immediately update page's `avatarUrl` state on upload / delete success, ensuring subsequent "Save Profile" form submit does not overwrite the photo.
- Secondary "Or use an image link" input for external URLs.
