# Plan: P3.3 — Distance on Match & Event Cards & Profile Location Setup

## 1. Goal
Calculate and display approximate peer and event distances ("Less than 1 km away", "3 km away", "2.3 km away") using the Haversine formula on match cards and event cards, while guaranteeing user location privacy (never exposing exact coordinates of peers). Allow users to search, set, and clear their own location on the profile setup page.

---

## 2. Privacy & Accuracy Architecture

### Distance Rounding Rules:
- **Between Users (Matches)**:
  - Nearest whole kilometre (`roundKm(dist, 1)`):
    - `< 1 km` -> rounded to `0` km -> formatted as `"Less than 1 km away"`.
    - `3.4 km` -> rounded to `3` km -> formatted as `"3 km away"`.
    - `3.6 km` -> rounded to `4` km -> formatted as `"4 km away"`.
  - **Privacy Guarantee**: Other users' `latitude` and `longitude` are NEVER sent to the client. The matches API returns only `distanceKm: number | null`.
- **Events**:
  - Event locations are already public pins on the map.
  - Distances to events rounded to `0.1 km` (`roundKm(dist, 0.1)`), formatted as e.g. `"2.3 km away"`.
- **Public Profile API (`/api/users/[id]`)**:
  - Strictly preserves existing privacy allow-list. Coordinates are never queried or serialized.

## 4. Pure Geospatial Module (`src/lib/geo.ts`)
- `haversineKm(lat1, lon1, lat2, lon2)`:
  - Radius: $R = 6371$ km.
  - Validity checks: finite numbers, `lat` in `[-90, 90]`, `lon` in `[-180, 180]`. Returns `null` if any coordinate is missing, null, or out-of-range.
  - Decision on `(0, 0)`: Not used as a default anywhere in SkillSwap (SkillSwap uses Bengaluru or Boston defaults). Mathematically valid GPS point, but if coordinates are null/undefined, returns `null`.
- `roundKm(distance: number, step: number): number`:
  - Rounds `distance` to nearest `step` (`1` for whole km, `0.1` for tenths).
- `formatDistance(distanceKm: number | null): string | null`:
  - Returns `null` when `distanceKm === null`.
  - Returns `"Less than 1 km away"` when `distanceKm === 0` or `distanceKm < 1`.
  - Returns `${distanceKm} km away` for whole-km integers.
  - Returns `${distanceKm.toFixed(1)} km away` for decimal distances.

## 6. Route Changes

### A. `GET /api/matches`
- Queries `currentUser.latitude` and `currentUser.longitude`.
- Attaches `currentUser.hasLocation: boolean` to `responsePayload.currentUser`.
- Computes `distanceKm: number | null` for each match item using `haversineKm` + `roundKm(..., 1)`.
- Candidate coordinates are stripped before returning.

### B. `GET /api/events`
- Loads session user's coordinates once.
- Attaches `distanceKm: number | null` (0.1 km precision) to each event item.

### C. `GET` & `PUT /api/user/profile`
- `updateProfileSchema` in `src/lib/validators/profile.ts`:
  - Accepts `latitude: z.number().min(-90).max(90).nullable().optional()`.
  - Accepts `longitude: z.number().min(-180).max(180).nullable().optional()`.
- `SAFE_PROFILE_SELECT`: selects `latitude: true, longitude: true` for the viewer's private own profile.
- `PUT`: updates `latitude` and `longitude` on the authenticated user.
