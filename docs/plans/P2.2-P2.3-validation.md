# Plan: Tasks P2.2 & P2.3 — Centralized Zod Validation & Standard Error Handling

## 1. Goal & Context
Implement declarative, strict request input validation across every API route in SkillSwap using the installed **Zod 4.4.3** library, and unify all error responses into a consistent, backward-compatible format:
`{ "error": "<readable message>", "details": [{ "field": "<name>", "message": "<reason>" }] }`.

Key constraints:
1. Preserve 100% backward-compatibility for successful responses and the `"error"` key on error responses.
2. Malformed or non-JSON payloads must safely return `400 Bad Request` instead of crashing with an unhandled 500 error.
3. Keep all P2.1 authentication and authorization guards intact, running session checks *before* input validation so unauthenticated callers always receive `401 Unauthorized`.
4. Validate all path params and search params with Zod schemas.
5. Prevent unknown field injection (`strip` behavior by default in Zod).

## 4. Adjustments and Compatibility Notes
1. **Password Length (Register):**
   The registration form in `src/app/auth/page.tsx` displays "Password (min 6 chars)", but the specification requires `8..72` characters (accounting for the bcrypt 72-byte truncation limit). We enforce `min(8)` and `max(72)` on the server. The UI properly displays the server's error message if an undersized password is submitted.
2. **Coordinate Handling (Create Event):**
   `src/components/CreateEventDialog.tsx` uses string text inputs for latitude and longitude and passes empty strings `""` when the user does not specify coordinates. The schema uses a preprocessor converting empty strings to `undefined` and parsing valid strings to numbers, ensuring that legitimate coordinates are bounded to `-90..90` and `-180..180` without rejecting blank optional inputs.
3. **Proficiency Enum Set:**
   Identified from `src/app/profile/setup/page.tsx` and `prisma/seed.ts` as strictly: `["Beginner", "Intermediate", "Advanced", "Expert"]`.
4. **Skill Categories:**
   Identified from database and seed as: `["Programming", "Design", "Languages", "Music", "Culinary", "Arts", "Personal Growth", "Games", "Health", "General"]`.
5. **JSON Parse Safety:**
   `parseBody` catches JSON syntax errors and returns `400 Bad Request` with `{ "error": "Invalid JSON in request body" }`, avoiding unexpected 500 crashes.
